# Changelog

## Unreleased

### Fixed

- WO-15 A (S26 finding 1): a staleness-detector response whose `results` elements are not objects — a well-formed envelope around bad elements — no longer raises out of `get_us_code_section`; it is `possibly_superseded.status: not_checked`, `reason: malformed_response`, with the body echoed, on a `success` lookup. A boolean `count` is malformed too. "A detector failure never fails the lookup" now binds against every shape.
- WO-15 B (S26 finding 2): `granule_id` is accepted only when it matches `USCODE-{year}-title{n}` followed by one or more hyphen-separated segments of letters and digits (the contract's grammar; 540 of 540 GovInfo-served ids on record, O86b), case-exact and as given. Anything else — a slash, dot, query character or whitespace included — is `invalid_argument` naming the id and stating nothing was fetched, before any request. Previously an id carrying `/../` reached the summary URL and its 404 read as "no package".
- WO-15 C (S26 finding 3): `not_checked` / `no_bound` is now a true statement. The detector's bound-error state is reset on every launch, so a failure on a remembered bound cannot outlive the launch that follows on the payload's own date; the `no_bound` branch cancels any live detector task and echoes no query; a speculative query issued on a remembered bound and cancelled is accounted for in-band (`prediction_note`); and a `currentthrough` that does not parse as a date is not remembered, so no speculative launch happens on one.

### Changed

- WO-15 D (S26 finding 4): HTML-to-text no longer builds a per-character index map on every conversion. Normalization is expressed as dropped ranges of the raw text, and marker offsets are translated with a prefix sum over those ranges, so the map's size is the number of ranges rather than the length of the payload (about 217 MB and 1 s on a synthetic 3.1M-character law before, a few MB and the parser's own time after). Nothing served changes: `structure` offsets, `total_chars`, `returned_chars`, the banner and `find` offsets are identical, asserted against the pre-change values and a differential test over the replaced algorithm.
- WO-15 G (R26 c): a `.env` is read only when the server runs from a repository checkout, and only the file at that checkout's root; it never walks up from the working directory, and an installed copy reads no `.env` at all — production configuration is the process environment alone. The keyless-startup contract is unchanged.
- WO-15 F (R26 a, b): `ruff format` is adopted — one reformatting-only commit, then `ruff format --check` in the quality workflow beside `ruff check`. CONTRIBUTING's commit-wrapping sentence no longer contradicts Ruff's 120-column code style.
- WO-15 H (R26 d): `mcp` is pinned exactly at 2.1.1, with the reason beside the pin (the tracer implements a middleware protocol the SDK labels provisional within 2.x, and the end-to-end trace test reaches a private attribute); CONTRIBUTING gains the rule that every dependency bump runs the full unit suite, trace tests included, before merge.
- WO-15 E: README and this changelog no longer describe the retired banner-in-content placement (the banner is `text.banner`; `content` is payload-only); the README config example's directory is spelled correctly; the stale test count is gone.

### Added

- R16 / WO-3: `get_us_code_section` accepts an optional `granule_id` (with optional `package_id`), selecting a granule directly — the fix for a same-citation, same-edition pair like the two `28 U.S.C. App. Rule 9`s. No URL is built from the id: the granule summary is fetched and its `txtLink` used verbatim; `package_id` is derived from the id's `USCODE-{year}-title{n}` prefix when not supplied and disclosed as `package_id_derived: true`; a non-USCODE id is rejected before any call; a summary 404 is `not_found` with the id echoed, distinct from upstream failure and rate-limit; `year` is ignored with a warning. Everything downstream of the fetch is the citation path's own code. The staleness detector runs on a `citation` passed alongside, and otherwise reports `not_checked` / `no_citation_for_detector`. The `ambiguous` message now names `granule_id` (and `year` when candidates differ by edition) instead of promising a by-id input the tool did not have. The server `instructions` string is brought to the contract: the indicator runs on every call, per-state next moves, and the composition recipe reframed as the widening step.
- WO-2 detector follow-ups (O44d/e/f/g): the `possibly_superseded` query now carries `lawtype:public` — a live section was measured firing on a 119th-Congress private law whose package `get_public_law` refuses under R6, and a private law's citation is by construction a named-party waiver, never an amendment — with the filter in the query so `count` stays upstream's; numbered appendix sections (`18 U.S.C. App. 1201`) run the detector on the measured `"{title} U.S.C. App. {section}"` form while appendix rules keep the `not_checked`/`no_measured_citation_form` fallback; and the `laws_indexed` caveat is pinned verbatim to the contract wording (a listing means the law *mentions* the section; only reading the listed law says whether the text changed), with the tool description carrying the same point.
- R14 / WO-1 staleness indicator: every `get_us_code_section` success carries `possibly_superseded`, a three-state object (`laws_indexed` / `none_indexed` / `not_checked`) from one `collection:PLAW publishdate:range({currentthrough + 1 day},) uscodecitation:"…"` query bounded by the returned edition's own `currentthrough`. `laws_indexed` carries the true upstream `count` and a capped `laws` list with capping stated; `none_indexed` carries the fixed not-a-currency-check caveat; `not_checked` surfaces the upstream status and body, a 429 as rate-limit, a timeout, or a malformed body, and is never collapsed into `none_indexed`. Every state echoes the exact `query` and `since`; a stripped "note" citation gets an in-band statement that the parent section was checked. A detector failure never fails the lookup, which waits at most 2 s for it after the text is ready. On the first lookup of an edition the query is issued as soon as the text fetch returns (its bound depends on the payload's `currentthrough`, which the search hit does not carry); on later lookups of that edition it is issued before the citation search on the remembered `currentthrough`, overlapping both upstream round trips, and verified against the payload before use — a mismatch discards it and re-issues on the exact bound.
- R12 content location in large payloads: both text tools take an optional `find` (case-insensitive literal substring) reporting the true occurrence count with offsets in the `start_char`/`total_chars` coordinate system, context snippets, a capped list that states the true total, and an explicit zero-match outcome — one call locates, one call reads. `get_us_code_section` successes also carry a `structure` block listing the payload's fields in order (`statute`, `sourcecredit`, typed notes with their headings) with a `start_char` each, derived only from the granule's upstream `field-start`/`field-end` markers (O36) and degrading to a disclosed omission — never a retrieval failure — when those markers are absent or unbalanced.
- R8 trace emission: setting `USCODE_MCP_TRACE_DIR` appends one JSONL line per handled MCP tool call (verbatim request and response, including error outcomes); an unusable directory fails the server at startup and a per-request write failure fails that request loudly.
- Initial MCP server scaffolding (implementation session): `uscode-mcp` Python package (`uv`-managed, `mcp` SDK 2.x) serving the four tools specified in `documentation/40-tools.md` — `get_us_code_section`, `search_us_code`, `get_public_law`, `search_public_laws` — over stdio (default) and streamable HTTP (`--transport http`).
- GovInfo API client with the three-outcome contract (success / upstream failure / rate-limited, never collapsed), citation normalization with the two mandatory strips (subsection, trailing "note"), HTML-to-text derivation with `currentthrough` provenance, and explicit (never silent) truncation windows.
- Unit test suite covering failure surfacing alongside the happy paths (`uv run pytest` reports the current count).
- `CONTRIBUTING.md` as the canonical source for code style, commit conventions, and the `documentation/` two-session model — resolves the conflicting commit-trailer guidance between `.claude/CLAUDE.md` and the workspace-level `CLAUDE.md` (#46, #78).
- `tests/test_conventions_sync.py` guards `AGENTS.md` and `.claude/CLAUDE.md` against drifting apart.

### Changed

- WO-5 (F4/F5/F6, O49): `search_public_laws` now carries `recall_caveat` on every success — the measured `uscodecitation` field gap when the query uses that field, otherwise a full-text caveat (a quoted phrase was measured missing a law containing it verbatim, O49c) — so no result set reads as complete. Its description names `publishdate:range(YYYY-MM-DD,)` and says `approveddate:range(...)` returns HTTP 500 upstream (two consumers followed the old description into that error, O49a); both search descriptions teach the `packageid:` scoping recipe (within-title section-level search, within-law presence test) with the presence-not-location caveat; `search_us_code` says `historical` is an argument, not a query term (O49b); `get_public_law` says `congress` + `law_number` names the public series only and a private-law number goes through the citation string.
- WO-4 (O47b, disposition of F3): the default `max_chars` on `get_us_code_section` and `get_public_law` is 20,000, down from 100,000. A 100,082-char window was measured not to reach the model inline on the current driver (replaced by a ~3 KB stand-in) while a 20,081-char window arrived. Nothing else about windowing changes: an explicit larger `max_chars` is honored, and the banner, `total_chars`, `next_start_char`, `find`, and `structure` are untouched. The descriptions and server instructions state the default and why.
- R13a — the `structure` block now rides only on locating calls (`start_char` 0 or omitted). A reading call gets the `omitted` form pointing back to a zero-offset request: the block is invariant per (section, year), and on the measured case it was 2,504 bytes wrapping a small read (O38). The `omitted` key is present in both shapes, so structure-present-or-disclosed still holds everywhere.
- R13b — every `structure` field now carries an exclusive `end_char` (the final field ends at `total_chars`), so `end_char - start_char` is both a field's extent and the `max_chars` needed to read it. `structure.note` now states that headings are upstream labels describing where a field *opens*, not what it contains — the measured hazard is a 38,154-char "Findings" note holding an entire Act (O38), a label pointing away from the answer.
- R13c — the in-band statement that the banner sits outside the offset coordinate system is now contractual on every bannered response rather than an un-specced nicety, so it cannot regress away.
- E12 in-band truncation banner — **superseded by R13c below (and by manifest version 7's `text.banner` check): the banner is carried on `text.banner` only, and `content` is payload text only; the entry is kept as history.** As first built, a truncated text response led `content` with a single bracketed line stating the window bounds, the true total, and the continuation `start_char` — ruled from finding F1, where a consumer handed complete and correct structured truncation fields still presented the window as the whole law. The structured fields are unchanged, so `find` and `structure` offsets keep their coordinate system; the banner is also returned on its own `banner` key so a caller can strip it deterministically.
- An absent **or blank** `GOVINFO_API_KEY` now fails the server at startup with a message naming the variable (stderr, exit 2), before any server object exists — a server that can serve nothing must be unmistakably down rather than up and wearing a misleading per-request error (R10 third amendment, from congressMCP's F31).
- Runtime dependencies now carry ceilings as well as floors (R9): `mcp>=2,<3`, `httpx>=0.27,<1`, `python-dotenv>=1.0,<2`. Raising a ceiling is a deliberate, tested change committed on its own.
- Disambiguation (`ambiguous`) outcomes state capping explicitly: `count` (true total), `candidates_shown`, `capped`, and a "showing N of M" message when the candidate list is page-capped — and no capping claim when it isn't.
- Appendix citations now resolve directly (`citation:"28 U.S.C. App. Rule 9"`, O24/E10); multi-hit appendix citations use the standard disambiguation list (which now also reports the true total `count`), and the redirect to `search_us_code` survives only as the zero-hit fallback (real for eliminated appendices like title 50's).
- The `get_public_law` `format="uslm"` not-available outcome now states the measured boundary (absent for congresses 104–112, present from the 113th on, O25) instead of "unmeasured".
- A set-but-blank `USCODE_MCP_TRACE_DIR` now fails the server at startup instead of silently disabling tracing; only an unset variable is the off switch (maintainer ruling, spec commit 2ebab5b).
- The GovInfo API key now travels only in the `X-Api-Key` request header, never as the `api_key` query parameter (R7, O22) — every URL the server builds, logs, or surfaces is key-free by construction.
- The `search_public_laws` recall caveat now states the measured structural gap from O21 (25/33 sampled recall, misses in every congress sampled from the 115th on) instead of the single-miss example.
