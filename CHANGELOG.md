- WO-26 B (S32 finding 2): a cut failure body says so. - WO-26 A (S32 finding 1): a cancelled call leaves nothing running. - WO-15 A (S26 finding 1): a staleness-detector response whose `results` elements are not objects — a well-formed envelope around bad elements — no longer raises out of `get_us_code_section`; it is `possibly_superseded.status: not_checked`, `reason: malformed_response`, with the body echoed, on a `success` lookup. - WO-15 B (S26 finding 2): `granule_id` is accepted only when it matches `USCODE-{year}-title{n}` followed by one or more hyphen-separated segments of letters and digits (the contract's grammar; 540 of 540 GovInfo-served ids on record, O86b), case-exact and as given. - WO-15 C (S26 finding 3): `not_checked` / `no_bound` is now a true statement. The detector's bound-error state is reset on every launch, so a failure on a remembered bound cannot outlive the launch that follows on the payload's own date; the `no_bound` branch cancels any live detector task and echoes no query; a speculative query issued on a remembered bound and cancelled is accounted for in-band (`prediction_note`); and a `currentthrough` that does not parse as a date is not remembered, so no speculative launch happens on one.

### Added

- WO-28 B (R34a): the by-id note. On a `get_us_code_section` success by `granule_id` with `citation` alongside, the citation search runs — owned by the call like the detector, overlapping the summary fetch — and the hits whose normalized id equals the fetched granule's are served, right after `possibly_superseded`, as `same_citation_candidates: {count, others: [{granule_id, title}], message}` with "This provision shares its citation with {N-1} other(s): {titles}. The person asking should be told."; a family of one serves no field. Without a citation, an appendix-rule id (`-app-` and a trailing `-rule{n}` after dup-segment removal) names its own citation and gets the same search and fields; a section id runs no search. The search is the resolution path's without a year, so it covers the current edition; an id from another edition, a failed search (500, 429, shape drift) and a capped page are each disclosed in the field (`not_checked` with a reason, or `capped`) and never fail the lookup.
- WO-28 A (R34a, E40/O115): the search-hit note for same-citation families. Two granules share a citation within an edition exactly when their ids are equal once every `-dup{N}` segment is removed. On every `search_us_code` page, each hit whose family has another member on the page carries `same_citation_on_page: {count, others: [{granule_id, title}]}` and a `note` — "This provision shares its citation with {N-1} other result(s) on this page: {titles}. The person asking should be told which is meant, or shown each as a distinct provision." — and a hit with no family member on the page carries neither. An id comparison over the page: no upstream request. `search_public_laws` hits carry nothing.
- R16 / WO-3: `get_us_code_section` accepts an optional `granule_id` (with optional `package_id`), selecting a granule directly — the fix for a same-citation, same-edition pair like the two `28 U.S.C. App. Rule 9`s. No URL is built from the id: the granule summary is fetched and its `txtLink` used verbatim; `package_id` is derived from the id's `USCODE-{year}-title{n}` prefix when not supplied and disclosed as `package_id_derived: true`; a non-USCODE id is rejected before any call; a summary 404 is `not_found` with the id echoed, distinct from upstream failure and rate-limit; `year` is ignored with a warning. Everything downstream of the fetch is the citation path's own code. The staleness detector runs on a `citation` passed alongside, and otherwise reports `not_checked` / `no_citation_for_detector`. The `ambiguous` message now names `granule_id` (and `year` when candidates differ by edition) instead of promising a by-id input the tool did not have. The server `instructions` string is brought to the contract: the indicator runs on every call, per-state next moves, and the composition recipe reframed as the widening step.
- WO-2 detector follow-ups (O44d/e/f/g): the `possibly_superseded` query now carries `lawtype:public` — a live section was measured firing on a 119th-Congress private law whose package `get_public_law` refuses under R6, and a private law's citation is by construction a named-party waiver, never an amendment — with the filter in the query so `count` stays upstream's; numbered appendix sections (`18 U.S.C. - R14 / WO-1 staleness indicator: every `get_us_code_section` success carries `possibly_superseded`, a three-state object (`laws_indexed` / `none_indexed` / `not_checked`) from one `collection:PLAW publishdate:range({currentthrough + 1 day},) uscodecitation:"…"` query bounded by the returned edition's own `currentthrough`. `laws_indexed` carries the true upstream `count` and a capped `laws` list with capping stated; `none_indexed` carries the fixed not-a-currency-check caveat; `not_checked` surfaces the upstream status and body, a 429 as rate-limit, a timeout, or a malformed body, and is never collapsed into `none_indexed`. Every state echoes the exact `query` and `since`; a stripped "note" citation gets an in-band statement that the parent section was checked. A detector failure never fails the lookup, which waits at most 2 s for it after the text is ready. On the first lookup of an edition the query is issued as soon as the text fetch returns (its bound depends on the payload's `currentthrough`, which the search hit does not carry); on later lookups of that edition it is issued before the citation search on the remembered `currentthrough`, overlapping both upstream round trips, and verified against the payload before use — a mismatch discards it and re-issues on the exact bound.
- R12 content location in large payloads: both text tools take an optional `find` (case-insensitive literal substring) reporting the true occurrence count with offsets in the `start_char`/`total_chars` coordinate system, context snippets, a capped list that states the true total, and an explicit zero-match outcome — one call locates, one call reads. `get_us_code_section` successes also carry a `structure` block listing the payload's fields in order (`statute`, `sourcecredit`, typed notes with their headings) with a `start_char` each, derived only from the granule's upstream `field-start`/`field-end` markers (O36) and degrading to a disclosed omission — never a retrieval failure — when those markers are absent or unbalanced.

The structured fields are unchanged, so `find` and `structure` offsets keep their coordinate system; the banner is also returned on its own `banner` key so a caller can strip it deterministically.
- An absent **or blank** `GOVINFO_API_KEY` now fails the server at startup with a message naming the variable (stderr, exit 2), before any server object exists — a server that can serve nothing must be unmistakably down rather than up and wearing a misleading per-request error (R10 third amendment, from congressMCP's F31).
- Runtime dependencies now carry ceilings as well as floors (R9): `mcp>=2,<3`, `httpx>=0.27,<1`, `python-dotenv>=1.0,<2`. Raising a ceiling is a deliberate, tested change committed on its own.
- Disambiguation (`ambiguous`) outcomes state capping explicitly: `count` (true total), `candidates_shown`, `capped`, and a "showing N of M" message when the candidate list is page-capped — and no capping claim when it isn't.
- Appendix citations now resolve directly (`citation:"28 U.S.C. App. Rule 9"`, O24/E10); multi-hit appendix citations use the standard disambiguation list (which now also reports the true total `count`), and the redirect to `search_us_code` survives only as the zero-hit fallback (real for eliminated appendices like title 50's).
- The `get_public_law` `format="uslm"` not-available outcome now states the measured boundary (absent for congresses 104–112, present from the 113th on, O25) instead of "unmeasured".
- A set-but-blank `USCODE_MCP_TRACE_DIR` now fails the server at startup instead of silently disabling tracing; only an unset variable is the off switch (maintainer ruling, spec commit 2ebab5b).
- The GovInfo API key now travels only in the `X-Api-Key` request header, never as the `api_key` query parameter (R7, O22) — every URL the server builds, logs, or surfaces is key-free by construction.
- The `search_public_laws` recall caveat now states the measured structural gap from O21 (25/33 sampled recall, misses in every congress sampled from the 115th on) instead of the single-miss example.
