## WO-1 — `possibly_superseded` on `get_us_code_section` (R14a/b/c; contract in `40-tools.md`, "Staleness indicator"; measured basis O43)

**Status:** CLOSED 2026-09-15 — built at implementation commit 1d42c52, verified O44 (artifact review, black-box probe, and the two ratification measurements). Disposition of the order's own error: its premise that the detector is independent of the text fetch was wrong (the bound needs `currentthrough` from the fetched HTML); the implementation's cold/warm two-regime design is ratified and the contract corrected (O44c). Both implementation decisions submitted for ratification are ratified as interim behavior and superseded by WO-2 below: appendix `not_checked`/`no_measured_citation_form` stays as the fallback for appendix rules, and the private-law question is answered by measurement (O44e), not by leaving the query alone. The order text below is kept as issued, for the record.

**What it is.** Every successful `get_us_code_section` response carries a `possibly_superseded` object saying whether GovInfo's PLAW index lists any public law published after the returned edition's `currentthrough` date against this section. It is an indicator in both directions and never a certification (R14a): a fire does not mean the text is stale, and silence does not mean it is current.

**The detector query.** One `POST /search` against `collection:PLAW`, exactly this shape:

```
collection:PLAW publishdate:range({since},) uscodecitation:"{title} U.S.C. {section}"
```

- `{since}` is the response's own `currentthrough` plus one day, ISO `YYYY-MM-DD`, open-ended upper bound. `currentthrough` is the value already parsed from the granule HTML comment for provenance (O5, O15), so the bound is correct for `year`-selected editions too. Never hard-code `congress:119` or a fixed date.
- `publishdate`, never `approveddate`: `approveddate` ranges return HTTP 500 upstream in every form tried (O43f). The `publishdate` form was measured equal to the `congress:119` ground truth (104 = 104) and exact at the Congress boundary (O43f).
- `{title}` and `{section}` are the section actually resolved, after the mandatory strips (subsection parenthetical O11, trailing "note" O16). Citation string form is `"42 U.S.C. 2210"` — the form measured in O43c/O43d/O43f.
- Same authentication as every other call (R7, `X-Api-Key`).

**Three states on a `status` discriminator, never two.**

| `status` | when | must carry |
|---|---|---|
| `laws_indexed` | upstream 200, `count` ≥ 1 | true upstream `count`; `laws[]` of `{package_id, title, date_issued}`, capped, with the cap and the true total stated whenever capping happened (the disambiguation-totals rule); the fixed caveat that this indicates possible change, not that the text is stale |
| `none_indexed` | upstream 200, `count` = 0 | the fixed caveat that this is NOT a currency check and that absence of a match is not evidence the text is current — the index misses about one in seven listed (law, section) pairs (O43b) and one in four in an earlier sample (O21) |
| `not_checked` | anything else: non-200, HTTP 429, timeout, malformed body | the upstream HTTP status and body verbatim, or the local reason (timeout, parse failure); 429 named as rate-limit, distinct from other failures (the three-outcomes rule, `40-tools.md`) |

Every state, including `not_checked`, echoes the exact `query` string sent and the `since` date it was bounded by. When `stripped_note` is true on the lookup, the object states in-band that the check ran against the parent section and that a law affecting only the note may be indexed against neither citation (O17/O18, O43b).

**Concurrency and failure isolation.** Issue the detector query concurrently with the `txtLink` fetch, not after it; measured from the spec session's network position a keep-alive request costs ~200 ms and the detector 210–280 ms, so run in parallel with the text fetch it adds ~0 wall-clock in the common case (O43e). A detector failure of any kind never fails the lookup: the section text is returned and the object says `not_checked`. Bound the wait — if the detector has not returned within a small budget after the text is ready, report `not_checked` with reason `timeout`; do not hold the text for it. The budget value is the implementation's choice; state it in the report.

**Do not.** Retrieve or parse the listed laws to resolve effective dates (declined, R14a). Use `approveddate` ranges (O43f). Collapse `not_checked` into `none_indexed`, or omit the object on any success. Add an opt-in flag (Q13 closed it). Cache detector results across lookups without stating so — and if you do cache, the cache key must include `since`, because two editions of the same section have different bounds. Write anything under `documentation/`.

**Unit tests (repo rule: failure paths, not just the happy path).** Mock the upstream at the HTTP layer and cover at least: 200 with hits → `laws_indexed` with `count` and capping stated when hits exceed the cap; 200 with zero hits → `none_indexed` with the caveat text; 500 → `not_checked` carrying status and body; 429 → `not_checked` naming rate-limit; timeout → `not_checked` with `timeout`, and the lookup still succeeds with full text; malformed JSON → `not_checked`; `stripped_note` lookup → query built on the parent section and the in-band statement present; a `year`-selected edition → `since` derived from that edition's `currentthrough`, not the newest; `query` and `since` present in every state. Mocked fixtures are not evidence of upstream behavior — they prove the code's handling of each shape, which is what they are for.

**Verification artifacts the spec session will ask for** (traces, not summaries — the recorded request and the recorded response, from real upstream calls):

1. `42 U.S.C. 2210` → `laws_indexed`. Expected to list PLAW-119publ74 (O43d); ground truth also lists publ21, and the detector missing it is the measured instrument gap, not a defect.
2. `17 U.S.C. 107` → `none_indexed` (O43d: silent, and no 119th-Congress law lists it).
3. A forced upstream failure (bad key on the detector call only, or a stubbed 500) → `not_checked` with the status and body, and the section text delivered in full alongside it.
4. `42 U.S.C. 2210 note` → the `stripped_note` in-band statement, query built on `42 U.S.C. 2210`.
5. `17 U.S.C. 107` with `year: 2023` → `since` equal to the 2023 edition's `currentthrough` plus one day, so the bound is visibly edition-relative.
6. The exact query strings for 1–5, and the measured wall-clock of a lookup with the detector on versus off, n stated.

The spec session will then black-box the same five inputs against the running server (as it did for R12 in O37 and R13 in O39) before marking this order closed and adding the manifest checks.

**Out of this order.** E15's api-surface extension is harness-side (mcp-e2e), not this server. The A/D isolation-cell runs and Group F questions are spec-session and maintainer work.

**Change 3 — pin the `laws_indexed` caveat to the contract wording.** Replace the current `laws_indexed` caveat with the text now pinned verbatim in `40-tools.md` ("INDICATOR ONLY — NOT A FINDING THAT THE TEXT CHANGED. ## WO-8 — collection scoping on the two search tools, and the README warning for the HTTP transport (R17; contract in `40-tools.md`, "Collection scoping"; measured basis O55)

**Status:** CLOSED 2026-09-20 — built at implementation commit a4e4e04, verified O57 as conforming to this order: the O55a calls replayed by the spec session with none of the foreign ids returned, the refusal shape as specified, refusals measured making no upstream request (a DNS-down run in the report's own artifacts, O57c), the detector-query paste working, the README warning in place. **The order itself was insufficient**: its quoted-phrase exemption lets an unbalanced quote carry a foreign clause upstream (O57e), and the build reads a clause's value short of the whole token (O57f). Both go to WO-9. The order text below is kept as issued, including the exemption now withdrawn.

**What it is.** Two things, one ruling. (1) `search_us_code` and `search_public_laws` each validate the collection clauses in `query` and refuse a non-conforming one before any upstream request. Today either tool runs whatever collection the caller names: `search_us_code` returned `PLAW-118publ31` for `collection:PLAW congress:118 docnumber:31` and 22,940 `BILLS` hits for `collection:BILLS congress:118`; `search_public_laws` returned `USCODE-2024-title17` with the public-law `recall_caveat` attached (O55a). That was the spec's defect — the old text said "unless the query already contains a `collection:` term" — and the contract is corrected. (2) A warning in the README that the HTTP transport is unauthenticated: anyone who can reach the port can call every tool and spend the GovInfo key's quota, so bind it to loopback unless something in front of it authenticates. The maintainer ruled that the transport itself does not change (R17b).

**The rule, restated so this order stands alone.** Find every collection clause in `query`: the word `collection` in any letter case, optional whitespace, a colon — anywhere outside a double-quoted phrase, inside parenthesized groups included. A clause conforms only if its value is the tool's own collection as one bare or double-quoted token, any letter case, no whitespace after the colon. All clauses conform → send the caller's query as written, prepending the tool's canonical clause only when the query has no clause (existing behavior, byte-unchanged for every query that works correctly today). Any clause does not conform → `outcome: out_of_scope_collection`, no upstream request, carrying the offending clause verbatim, the tool's collection, the name of the tool that serves the named collection when there is one, and a statement that no search was run.

**Why refuse instead of overriding.** Upstream unions repeated collection terms: `collection:USCODE collection:PLAW "fair use"` returns 18 = 11 + 7, and so does the foreign clause nested in parentheses (O55c). Prepending the right clause beside a wrong one scopes nothing. And `collection: USCODE` with a space is not read by upstream as a restriction at all (O55d) — under a substring presence test it suppresses the prepend and unscopes the tool entirely, so it is refused, not passed.

**Do not.** Parenthesize or otherwise rewrite the caller's query — a top-level OR was measured not to escape the prepended clause (O55e). Strip or repair a non-conforming clause. Filter foreign hits out of a result after the fact (the `count` would then lie). Apply the rule to the queries the server builds itself (citation resolution, the `possibly_superseded` detector). Add authentication, a loopback-only restriction, or any other change to the HTTP transport. Act on the audit's other findings (key egress, trace permissions, dependency auditing) — they are with the maintainer as Q15. Write under `documentation/`.

**Unit tests.** Per tool, asserting on the request the mocked upstream did or did not receive: no clause → canonical clause prepended; conforming clause in each measured spelling (`collection:USCODE`, lowercase value, uppercase field name, quoted value) → query sent as written, not double-prepended; the detector's echoed query shape (`collection:PLAW lawtype:public publishdate:range(…) uscodecitation:"…"`) accepted by `search_public_laws` unchanged. Refusals, each asserting zero upstream requests and the `out_of_scope_collection` shape: the other tool's collection (with the pointer to that tool), a third collection (`BILLS`, no pointer), `collection:(USCODE OR PLAW)`, a conforming clause plus a foreign one, a foreign clause nested in parentheses, the space-after-colon form, a negated clause, an empty value, mixed-case foreign (`Collection:plaw` on `search_us_code`). Not a refusal: `collection:` inside a double-quoted phrase. The refusal is traced like any other response (R8). A note on these tests, from this directory's standing rules: they and the validator will be written from the same reading of this order, so they prove the two agree with each other, not with GovInfo — the inputs below are the ones no one here authored.

**Verification artifacts** (real upstream, R8 trace on, under the gitignored `runs/`): replay the five served calls of O55a — same tools, same arguments, in `runs/2026-09-20-e18-spec-probe/probe.py` — and return the trace: the two controls unchanged (`collection:USCODE "fair use"` echoed, 11; PLAW 118/31, 1), the three foreign-collection calls refused with the shape above. Add: `search_us_code` with `collection: USCODE "fair use"` (refused), with `collection:uscode "fair use"` (success, 11 at time of writing, query echoed as sent), and `search_public_laws` with a `query` pasted verbatim from a live `possibly_superseded` object (success). For the refusals, the evidence that no upstream request was made — whatever the server can honestly show (request log, timing); say which. For the README: the diff. ## WO-9 — collection scoping, corrected: no quoted-phrase exemption, whole-token values (R17; contract in `40-tools.md`, "Collection scoping"; measured basis O57e/O57f)

**Status:** OPEN, issued 2026-09-20.

**What it is.** WO-8 was built exactly to its order and the order was wrong. `search_us_code` with `"fair use collection:PLAW` — a single unbalanced double quote — returns 18 hits, 11 USCODE and 7 PLAW; `"fair \" collection:PLAW "fair use"` does the same; `search_public_laws` with `"appropriations collection:USCODE` returns 7,552 hits, 100 of 100 on the page USCODE, under the public-law `recall_caveat` (O57e). WO-8 told the validator to skip clauses inside a double-quoted phrase; upstream does not treat an unterminated or escaped quote as a phrase and honors the clause. Two changes. **(1) No exemptions.** A collection clause is the letters `collection` (any case), optional whitespace, a colon — anywhere in the string. Quotes do not hide it, parentheses do not hide it, preceding characters do not hide it (`subcollection:PLAW` is a clause). Remove the quote handling; do not replace it with a better one — any quote parser the server runs is one that can disagree with upstream's. **(2) Whole-token values.** The value runs from the colon to the next whitespace, closing parenthesis, or end of query; when it opens with a double quote, through the next double quote, which must be followed by whitespace, `)`, or the end. It conforms only if the whole value equals the tool's collection, bare or double-quoted, any case. Today `collection:USCODE*`, `USCODE,PLAW`, `USCODE~`, `USCODE^2`, `USCODE/PLAW`, `USCODE|PLAW`, `USCODE.PLAW`, `USCODE:PLAW` and `USCODE"PLAW"` pass validation and reach upstream, where each returns HTTP 500 (O57f) — no foreign hit measured, but they are requests the contract says are never sent.

**Refusal message.** When the offending clause sits inside double quotes, the `message` adds that a phrase containing `collection:` must be written without the colon. Otherwise the `out_of_scope_collection` shape is unchanged.

**Do not.** Change anything O57 verified: the refusal shape, the prepend-only-when-absent rule, the echo of the caller's query as sent, conforming spellings, the README. Add operator analysis for conforming clauses — `AND NOT collection:USCODE`, `OR collection:USCODE` and `NOT collection:USCODE` were measured staying in-collection (O57g). Write under `documentation/`.

**Unit tests.** Refused, zero upstream requests each: the three O57e queries verbatim; a foreign clause inside a *balanced* quoted phrase (`"x collection:PLAW y"`); `"the collection: of duties"` with the colon advice in the message; `subcollection:PLAW`; each O57f value form. Still accepted, sent as written: every conforming spelling from WO-8, `collection:USCODE)` closing a group as in `(collection:USCODE "fair use")`, a conforming quoted value followed by `)`. The WO-8 tests that assert the quoted-phrase exemption are inverted, not deleted.

**Verification artifacts** (real upstream, R8 trace on, under `runs/`): replay `runs/2026-09-20-wo8-spec-probe/probe.py`, `probe2.py` and `probe3.py` — 52 calls — and return the traces.
