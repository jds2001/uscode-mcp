That's the only case where the arithmetic is forced rather than optional. If that shows up in real traffic, the fix probably isn't `fields` anyway — it's returning `statute` first with the notes windowed behind it, which needs no new vocabulary in the request.

O28 — Response-envelope and trace-shape measurement, by black-box probe: the spec session launched the built server (`uv run uscode-mcp`, stdio) with a trace directory set, drove it over its public MCP wire (initialize, tools/list, six tools/call), and read the resulting R8 trace. No implementation source was read. Findings:

- Tool surface: `get_us_code_section(citation, title, section, year, max_chars, start_char)`, `search_us_code(query*, page_size, offset_mark, historical)`, `get_public_law(congress, law_number, citation, format, max_chars, start_char)`, `search_public_laws(query*, page_size, offset_mark)`.

O40b — the boundary on O40's cost claim, stated because the acceptance rests on it. "Model context is 1×" is an **inference from consumer behavior**, not a measurement: consumers quote `recall_caveat`, `find` fields and offsets that exist only in the envelope copy, which shows they read the serialized copy — it does not show the host withheld the other one. Standard-behavior note (secondary, not a measurement): the MCP specification asks a tool returning structured content to also return functionally equivalent unstructured content for backwards compatibility, giving serialized JSON in a text block as its example. That is the documented reason this shape is not an implementation choice; it is cited as spec text, not as something measured here. This is the MCP SDK's standard dual emission for structured-output tools (compat text block + typed block), not an implementation choice. Cost profile: model context is 1× — consumers demonstrably read the JSON envelope copy (they quote `recall_caveat`, `find` fields, and offsets, which exist only in the envelope); the 2× lands on wire, trace files, and memory.
